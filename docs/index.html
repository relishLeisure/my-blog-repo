重观千与千寻

October 5, 2026

剧情¶

小女孩千寻坐在车上，父母在前排，他们在前排载着千寻搬去新家，但是千寻其实很不情愿，经过新学校时偷偷做了个鬼脸，千寻的父母对她似乎不是很关心。

父亲开车走一条小路停在一个门洞前，出于好奇爸爸妈妈决定进去玩，千寻本来不想进去，但是很害怕还是跟着爸妈一起进去。进去后从通道出来，发现是一些奇怪风格的建筑，父亲认为是90年代泡沫经济的时候兴建的主题公园。爸爸妈妈闻到食物的香味，于是就继续往里面走，但是千寻并不情愿地往里面走。

他们走到一条街道，爸爸发现有美味的食物，直接就叫妈妈一起开吃，说“无论是现金还是信用卡”，到时候付给老板就行了。他们开动后吃了很多，而且停不下来了。千寻害怕又无奈，自己到附近看看，经过一个桥，桥对面是一座多层的建筑。在这里碰到了白龙，白龙说天快黑了让她快跑到河边，千寻先跑到食物店，发现了两个人在吃东西，他们转过头来她才发现是猪，被吓坏了。此时她还不知道这两头猪就是她的父母。

千寻跑到河边，发现进来的通道在河的对岸，有一条装饰着彩灯的船靠岸，很多奇怪的乘客从船上走下来。千寻恐惧地蹲下，发现自己正在变得透明，这时白龙来了，给她一个小丸子——“不吃这里的东西，你会消失的”。

白龙把千寻带入汤屋，过桥的路上千寻的人类气息被闻到。进入汤屋后，白龙让千寻自己去找锅炉爷爷，求让他给千寻一份工作。千寻到了锅炉房，长着六条腿的锅炉爷爷正在工作，这里有很多小煤灰球在搬运煤块，千寻求锅炉爷爷给她一份工作，但是锅炉爷爷说已经满了，一只小煤灰球被煤块压扁，千寻帮它把煤块搬运并扔进锅炉之中。千寻再次求锅炉爷爷给她一份工作，但是锅炉爷爷说已经满了，小煤灰球们抗议。

侍女玲下来后，锅炉爷爷解释说千寻是他的小外甥女，请玲带千寻去汤婆婆那里，试试能否给千寻一份工作。千寻偷偷上了楼，汤婆婆不愿意让千寻在这里工作，但是千寻一直坚持在这里工作，汤婆婆不情愿地让千寻签订了契约，但是夺走了千寻的名字，从此她叫做小千。

小千被白龙安排协助玲，其他人幸灾乐祸。第二天白龙带小千去看变成猪的小千的父母，但是他们已经变成只知道吃喝睡觉的猪了。“不要吃太多，会被杀掉的”，小千说。

小千和玲被安排到清理大浴室，其他人幸灾乐祸，千寻工作中看到无脸男在淋雨，给他留门，无脸男进入了汤屋。小千在无脸男帮助下拿到了药浴的牌子，之后无脸男再拿出一堆牌子，小千却说她不需要了。

此时，腐烂神来到汤屋，他身上的气味将别人吓走，小千熏得炸了毛，连饭菜都腐败了。进入大浴室，小千艰难地工作，掉进浴盆被托起，她发现客人身上有一根刺，汤婆婆意识到这不是腐烂神，召集人们将绳子绑在刺上，大家一起拔，在合力之下，刺被拔出，原来那是自行车的把手，紧跟着一大堆垃圾都喷涌而出，有电视机、马桶等等，是人类丢弃的垃圾。

原来客人其实是河神，河神给了小千一个团子，化身飞龙洒脱地飞走了。河神留下的垃圾中也有很多砂金，汤婆婆夸赞小千。

深夜蛤蟆到大浴室找砂金，无脸男变出一些砂金，吃下了蛤蟆，获得了蛤蟆的声音。

白龙被一群纸鸟追逐，受了重伤，小千救下白龙，白龙飞到楼上汤婆婆那里，一只纸鸟偷偷粘在小千背后。小千听汤婆婆说白龙没救了，等汤婆婆去楼下，纸鸟变钱婆婆，和汤婆婆一模一样，她将娃娃“坊”变成小老鼠，把鸟变成小鸟，把三个头颅变成娃娃“坊”，白龙偷袭切破坏了纸鸟，将千寻、小老鼠和小鸟带到锅炉房，千寻将半个河神的团子塞进白龙嘴里，白龙吐出偷盗钱婆婆的印章并恢复了人身。

无脸男又吃了两个人，变化出很多砂金，享受被众人追捧簇拥的感觉。现在汤婆婆都拿他没办法，小千给他吃了剩下的团子，这本是她留着用来救她的父母的，无脸男吐出吃掉的人，变回原状。

小千要搭乘电车去钱婆婆那里，归还印章，小老鼠、小鸟、无脸男也跟着一起去，汤婆婆招待他们，他们一起纺线，编织了一根紫色头绳送给小千。白龙接回小千，飞回来的路上，小千想起了一个名字——“琥珀川”——已经变成土地的故乡的一条河，在千寻的提醒下白龙想起了自己的名字“赈早见琥珀主”，小千说“好美啊，像神明的名字”。

汤婆婆让小千从一群猪中找出她的爸爸妈妈，只有一次机会，小千说这里面没有她的爸爸妈妈，小千猜对了。

回去路上，白龙让千寻不要回头，千寻爸爸的车上已经积了一层树枝树叶，座位上也有一层灰了，千寻回头看了看门洞，这似乎是一场梦，小千转头离开，头上紫色的新头带闪光——这并不是一场梦。

记录¶

1.没有工作就会消失，无法生存就会消失，回归虚无，无法存在这个世界之上，无法感受，要生存就要工作谋生；

2.汤婆婆代表追逐利益，对神明谄媚恭维，对下级严厉。钱婆婆则代表，回归朴素自然宁静的田园生活;

3.千寻的父母缺乏敬畏之心，被变成猪，放纵自己，只留动物本能而活；

4.“坊”在日本代表少爷、小公子、小宝贝，巨婴“坊”被宠溺放纵，说屋外都是细菌，只呆在自己的房间，任性不能体会别人的痛苦。

5.无脸男孤独寂寞，被人忽视，通过讨好别人的方式得到安慰认可，自己没有本体和个性，向外追求自己的存在被环境带着走，“在汤屋他会变坏的”，最终留在钱婆婆那里，在平静生活中找回自我。

和很多电影一样，《千与千寻》是一部关于成长、回归自我的电影，我们追求的东西，从来都不在外界，而在我们的内心。千是被夺走后的名字，千寻是原本的名字，千寻并没有不同，但是记得我们从哪里而来才不会迷失自我。自我藏在身体、情绪里面，而不是完全被金钱、名誉、规则束缚和定义。在追逐名利，泛起泡沫的世界，有的人无法控制自己的欲望，迷失了自我成了被人宰割的动物；有的人出身富贵但是被骄纵，任性而脆弱；有的人缺乏自尊，随波逐流，追逐大家追逐的东西，活在别人的眼里，为别人而活……

因为我自己存在很多问题，所以在他们每个人身上都能看到我自己。

宫崎骏在电影中也反映了一些环境、社会的问题，比如泡沫经济、环境污染等，人们贪婪地满足欲望，缺乏对神明和自然的敬畏。

开端：继业者战争¶

近日看柳月刀讲解继业者战争的视频，一连看了十期。他的讲述风格生动，人物、情节与悬念的安排很恰当，讲解富有激情，很容易让人沉浸其中。有感于亚历山大大帝去世后四年间继业者之间的争斗，便克服惰性整理了这份笔记。我对这段历史了解不深，只当作新鲜故事记录，内容可能存在不少错漏。让豆包帮忙整理

一、亚历山大去世前的传闻与死因¶

据说亚历山大率军进入巴比伦城之前，当地占星师曾劝阻他，称入城会遭遇不幸，若一定要进也不要从西门进入。当时巴比伦的占星师还主管部分工程建造事务。

在一次宴会之后，亚历山大开始持续低烧，不久后便去世。我个人怀疑他很可能是被下毒：此前他在战斗中受过重伤都挺了过来，身体素质素来强健，却如此快速病逝，十分不寻常。能正面击败数万敌军的大帝，最终折损于人性的贪婪暗算。

二、亚历山大去世时的子嗣¶

他有一个私生子赫拉克勒斯；他的波斯妻子 罗克珊娜（Roxana） 当时已近临盆（约十几天后分娩），腹中孩子即后来的亚历山大四世。

三、核心人物¶

（一）近身护卫官¶

印度马利战役后，朴塞斯塔斯因救驾有功，被破格增补为第8位近身护卫官。但赫费斯提翁已于公元前324年在埃克巴坦那病逝，因此公元前323年亚历山大去世时，在册的近身护卫官共7位：

  1. 佩尔狄卡斯（Perdiccas） —— 亚历山大死后担任帝国摄政
  2. 托勒密（Ptolemy） —— 后来的埃及托勒密一世
  3. 列昂纳托斯（Leonnatus） —— 马其顿贵族，继业者之一，死于拉米亚战争
  4. 利西马科斯（Lysimachus） —— 没提到
  5. 培松（Peithon） —— 米底总督
  6. 阿瑞斯托诺斯（Aristonous） —— 没提到
  7. 朴塞斯塔斯（Peucestas） —— 总督东部地区，马利战役中救下亚历山大性命，后任波斯总督，主动推行波斯服饰与习俗

补充：赫费斯提翁（Hephaestion）原本是近身护卫官之一，据说是亚历山大的同性伴侣，公元前324年病逝，因此不在此列。

（二）其他重要人物¶
  • 安提帕特（Antipater）：马其顿老臣、摄政，将三个女儿分别嫁给佩尔狄卡斯、托勒密与克拉特鲁斯（Craterus）
  • 安提柯（Antigonus）：弗里吉亚总督（原文误记为“安条克”，安条克为后世塞琉古王朝君主，与此时时间线不符）
  • 墨勒阿革洛斯（Meleager）：步兵军官
  • 安提贞尼斯（Antigenes）：银盾兵将领
  • 克利奥帕特拉（Cleopatra）：亚历山大的妹妹
  • 阿尔塞塔斯（Alcetas）：佩尔狄卡斯的弟弟
  • 克拉特鲁斯（Craterus）：亚历山大去世前，命他带领一万余名退伍老兵返回马其顿。

四、亚历山大死后的主要事件¶

亚历山大去世后，佩尔狄卡斯以摄政身份召开会议。 去世当日，步兵军官墨勒阿革洛斯带兵冲入大帝的寝宫，与摄政佩尔狄卡斯谈判；佩尔狄卡斯随后逃离，召集骑兵力量。经过双方谈判，重新制定了四位核心护卫人员。

列昂纳托斯率军返回马其顿，希望与亚历山大的妹妹克利奥帕特拉成婚，最终在与反叛希腊人的拉米亚战争中战死。

托勒密主动请求前往埃及就任总督，后来截下了亚历山大的遗体与灵柩（佩尔狄卡斯原计划送往马其顿王陵安葬），在埃及建立了延续数百年的托勒密王朝。

佩尔狄卡斯率领培松、银盾兵将领安提贞尼斯等人征讨托勒密，渡河作战时遭遇惨败：原本计划用大象在上游阻挡水流，反而弄巧成拙，导致上千名士兵被淹死。 随后培松与安提贞尼斯联手刺杀了佩尔狄卡斯，并宣称佩尔狄卡斯为叛国者。

欧迈尼斯对阵克拉特鲁斯的战役中击败克拉特鲁斯的欧洲势力，但欧迈尼斯随后被安提柯击败，仅剩600人退守在一座小堡垒中。

五、个人感想¶

  1. 乱世之中，忠良难寻。将领甚至约束不住贪婪的士兵，士兵为钱财而战，将领也因贪婪而自相残杀，庞大的帝国很快就分崩离析。
  2. 欧迈尼斯与克拉特鲁斯作战时甚至要设法不让士兵知道对面的将领是克拉特鲁斯，以免士兵临阵倒戈。
  3. 佩尔狄卡斯、欧迈尼斯应该是真正忠于王室的人，但世事难预料、局势也瞬息万变、无人能把握全局。
  4. 从佩尔狄卡斯的弟弟阿尔塞塔斯的行事作风，以及阿尔塞塔斯死后仍被当地人纪念来看，他们兄弟应该是坚守品行与荣誉的人，我不确定，毕竟历史虚虚实实。
  5. 欲望、贪婪与嗜血蒙蔽了很多人，谎言与背叛也困住了很多人，但也有人始终坚持荣誉与忠诚；而懦弱的君主则被人当作傀儡摆布。

1.去掉多行空格¶

Python 脚本：递归去掉文件夹内所有 .md 文件多个连续空行替换为单个空行

import re
import sys
from pathlib import Path

def compress_blank_lines(directory):
    # 匹配 2 个或更多连续换行符（即两个或以上的空行，中间允许包含空格或制表符）
    # \n 后面跟着至少 2 个 ([ \t]*\n)
    pattern = re.compile(r'\n([ \t]*\n){1,}')
    
    # 获取目录下所有 .md 文件（递归）
    folder_path = Path(directory)
    md_files = folder_path.rglob('*.md')
    
    modified_count = 0
    
    print(f"开始扫描目录: {folder_path.resolve()}")
    
    for file_path in md_files:
        try:
            # 以 UTF-8 编码读取文件内容
            with open(file_path, 'r', encoding='utf-8') as f:
                content = f.read()
                
            # 执行正则替换
            new_content = pattern.sub('\n\n', content)
            
            # 如果内容发生变化，则覆盖写入原文件
            if new_content != content:
                with open(file_path, 'w', encoding='utf-8') as f:
                    f.write(new_content)
                print(f"已清理空行: {file_path}")
                modified_count += 1
                
        except Exception as e:
            print(f"读取或写入文件 {file_path} 时出错: {e}")
            
    print(f"\n处理完成！共修改了 {modified_count} 个 .md 文件。")

if __name__ == "__main__":
    if len(sys.argv) > 1:
        TARGET_DIR = sys.argv[1]
    else:
        TARGET_DIR = '.'
    compress_blank_lines(TARGET_DIR)

    # ^ 匹配行首 (配合 re.MULTILINE 使用)
    # \s+ 匹配 ### 后面的空格
    md_h3_pattern = re.compile(r'^###\s+(.*?)\s*$', re.MULTILINE)

            # 1. 先替换 HTML 标签的 H3
            new_content = html_h3_pattern.sub(r'**\1**', content)
            # 2. 再替换 Markdown 原生语法的 H3

这行 * * * * * /var/tmp/.crond/upd >/dev/null 2>&1 的意思是：每分钟（五个星号代表每分钟） 执行一次 /var/tmp/.crond/upd 这个脚本，并且把所有的输出和错误信息都丢弃（>/dev/null 2>&1），让你在日常使用中完全察觉不到。

值得注意的是，这个脚本指向的是 /var/tmp/.crond/upd，这说明除了你之前发现的 /tmp/.crond，木马在 /var/tmp/ 目录下还放了一个备用的执行源。

这个目录下的文件结构是非常典型的自动化攻击脚本包：

  • a / upd / run：这些通常是 Shell 脚本，负责下载木马的更新、检查运行状态、并把自身写入 crontab 确保不死。
  • bash.pid：用来记录反弹 Shell 后门的进程号（PID）。
  • cron.d：伪造的定时任务目录名，可能存放了其他用于持久化的配置。
  • h32 / h64：极其典型的恶意挖矿/后门程序二进制文件！它们通常代表针对 32 位和 64 位系统编译的木马实体。
  • java / x：黑客经常将恶意程序重命名为 java 等常见进程名，以躲避管理员的粗略检查。x 可能是一个隐藏的执行入口或脚本。

2.处理¶

第一步：删除定时任务 必须先删定时任务，否则后面的操作毫无意义。

  1. 查看定时任务

    crontab -l
# 输出
* * * * * /var/tmp/.crond/upd >/dev/null 2>&1

  2. 输入命令编辑当前用户的定时任务：

    crontab -e

  3. 找到 * * * * * /var/tmp/.crond/upd >/dev/null 2>&1 这一行，将其彻底删除。

    • 如果是 vi 编辑器，将光标移动到该行，连续按两次 d 键（dd）即可删除。然后输入 :wq 按回车保存退出。
    • 如果是 nano 编辑器，直接用退格键删掉，然后按 Ctrl+O 回车保存，Ctrl+X 退出。

  4. 再次运行 crontab -l，确认没有任何输出，或者该恶意行已被成功移除。

第二步：彻底击杀所有恶意进程 现在定时任务已经不在了，木马失去了“复活甲”，我们可以放心动手杀进程了。请依次执行：

pkill -9 -f "/var/tmp/.crond/"

第三步：连根拔起，删除所有恶意文件 清理所有查出的木马目录：

# 删除 /tmp 下的木马主目录
rm -rf /tmp/.crond
# 删除 /var/tmp 下的更新脚本或备份目录

__global__ void convolution_1d_kernel(const float* input, const float* kernel, float* output,
                                      int input_size, int kernel_size) {
    int tid = blockIdx.x * blockDim.x + threadIdx.x; 
    float sum = 0.0f;
    if (tid < input_size - kernel_size + 1) {
        for (int i=0; i<kernel_size; ++i) {
            sum += input[tid + i] * kernel[i];
        }
        output[tid] = sum;
    }
}

// input, kernel, output are device pointers (i.e. pointers to memory on the GPU)
extern "C" void solve(const float* input, const float* kernel, float* output, int input_size,
                      int kernel_size) {
    int output_size = input_size - kernel_size + 1;
    int threadsPerBlock = 256;
    int blocksPerGrid = (output_size + threadsPerBlock - 1) / threadsPerBlock;

    convolution_1d_kernel<<<blocksPerGrid, threadsPerBlock>>>(input, kernel, output, input_size,
                                                              kernel_size);
    cudaDeviceSynchronize();
}

__global__ void matrix_transpose_kernel(const float* input, float* output, int rows, int cols) {
    int x = blockIdx.x * blockDim.x + threadIdx.x;
    int y = blockIdx.y * blockDim.y + threadIdx.y;
    if (y < rows && x < cols) {
        // input[row, col] 放到 output[col, row]
        int input_idx = y * cols + x;
        int output_idx = x * rows + y;
        output[output_idx] = input[input_idx];
    }
}

}

Swish-Gated Linear Unit¶

SWiGLU is defined as:

  1. Split input into two halves: x1 and x2
  2. silu(x1) = x1 / (1 + exp(- x1))
  3. res = silu(x1) * x2

CUDA

#include <cuda_runtime.h>

__global__ void swiglu_kernel(const float* input, float* output, int halfN) {
    for (int i=0; i<halfN; ++i) {
        float silu = input[i] / (1 + exp(-input[i]));
        output[i] = silu * input[i+halfN];
    }
}

// input, output are device pointers
extern "C" void solve(const float* input, float* output, int N) {
    int halfN = N / 2;
    int threadsPerBlock = 256;
    int blocksPerGrid = (halfN + threadsPerBlock - 1) / threadsPerBlock;

    swiglu_kernel<<<blocksPerGrid, threadsPerBlock>>>(input, output, halfN);
    cudaDeviceSynchronize();
}

原理¶

  1. 认为车致信号为脉冲信号，与信道产生卷积
  2. 通过UNet恢复稀疏信号X，波束成形 + Music 滤波
  3. 稀疏信号X与固定的冲激函数进行反卷积，恢复车辆信号
  4. 损失函数 = MSE + X的L1正则

1. 这个仓库是什么¶

这是 van den Ende 等人 DAS 交通监测论文的代码（仓库名 van-den-Ende-DDCN）。DAS = 分布式光纤声学传感：埋在路边的光纤记 录车辆经过时的应变率信号。论文的核心问题是稀疏反卷积（Deep Deconvolution）：光纤记录到的是“车辆脉冲序列 × 光纤冲激响应

  • 训练一个 UNet 把观测信号还原成稀疏脉冲，再做波束形成估计车速、恢复车辆轨迹。

2. 项目结构¶

  • models.py — 核心：UNet/ResNet 反卷积模型、DataGenerator 数据增强、CallBacks 回调

  • beamforming.py — 多锥度（multitaper）协方差估计 + MUSIC/常规波束形成，在慢度网格上扫描

  • ISTA.py — 经典稀疏反卷积基线：FISTA 迭代软阈值（JAX 实现）

  • utils.py — FFT_roll（慢度时移对齐）、peak_projection（峰值检测）、match_peaks（与人工拾取匹配评估）

  • Fig*.ipynb — 论文全部插图，同时是使用示例：Fig2_impulse_response（冲激响应）、Fig4_architecture（网络结构）、 FigS1_training_curves（训练曲线）、Fig10/11、Figs6-9（评估）

  • requirements.txt — numpy/scipy/tensorflow>=2.3/jax/numba/spectrum/h5py 等

  • data.tar\data\ — 实际数据目录：DAS_data.h5（1.6 GB 主记录）、kernel.npy（冲激响应）、saved-model.h5（预训练权重）、 multicars_extract.npy、picks_forward/backward.npy（人工拾取的车辆轨迹）、coords_Teil.npy（光纤几何坐标）、logs/（训 练 TensorBoard 日志）

3. 核心模型与训练方法¶

观测模型：y = h ⊛ x + n，其中 h 是已知的冲激响应（kernel.npy，实测自单辆车经过）。

  • 网络前向（models.py:280）：UNet 输出稀疏脉冲图 x_hat，再用固定卷积 h 得到重建观测 y_hat。训练时只有 y_hat 参与监督， 这就是“物理约束自监督”反卷积。（意思是：UNet 输出稀疏信息 x_hat，也就是车致信号，通过固定卷积 h 得到 y_hat; 训练时只有 y_hat 参与监督意思是 损失函数计算 y_hat 和 y）
  • 损失（models.py:290）：total = ‖y − y_hat‖² + λ·‖x_hat‖₁，即拟合项 + 稀疏项。论文里 λ = 10（代码中叫 rho/lam），训练 曲线按 rho·l1 绘制以体现贡献占比。（正则化）
  • 结构：kernel=(3,5)、激活 swish、正交初始化、Adam lr=5e-4；推理用配置 f0=8, blocks=3, AA=False, bn=False, dropout=1.0（dropout 实际是 GaussianNoise，见 models.py:356）。下采样用 MaxBlurPool（抗混叠），上采样双线性 + skip 连接，最后 relu 输出保证非负脉冲。
  • 数据：DataGenerator（models.py:17）从长记录里随机截 win 宽窗口，并做时间/通道翻转增强；每个 epoch 重新采样。
  • 训练流程：约 1000 epoch，ModelCheckpoint 按 val_loss 保存最佳权重 → saved-model.h5，TensorBoard 记录 loss/l2/l1（见 FigS1_training_curves 与 logs/）。

我的理解（修正版）¶ 

y (观测) → UNet → x_hat (稀疏脉冲图)
                   │
                   ├─ 与已知冲激响应 h 卷积 → y_hat (重建观测)
                   │     损失 = MSE(y, y_hat) + λ·‖x_hat‖₁
                   │
                   └─ 推理时只取 x_hat → FFT_roll 慢度对齐 → 波束形成扫描 → 轨迹

三处小修正：

  • UNet 输出在代码里叫 x_hat。
  • L1 正则加在输出信号 x_hat 上，不是网络权重上——它不是“参数稀疏化”，而是物理先验“车辆事件在时空上是稀疏的”。模型学的是“去卷积”，因为只有把脉冲放在车辆事件位置，h⊛x̂ 才能匹配 y。
  • 波束形成是对 x_hat 做的，不是 y_hat。Fig10 cell 10 把 UNet 输出 x 存入 "deep" 类别，之后才做 FFT_roll + Beamformer。

Q1：你的数据是 1000 Hz¶

采样率会影响三处，都需要对齐：

  • 时间窗：模型推理用 win=1024，50 Hz 时是 20.5 s，足够覆盖一次完整过车（24 通道 × 3.2 m ≈ 77 m，80 km/h 约 3.5 s）。
  • 冲激响应 h：kernel.npy 有 866 个采样点，50/80 Hz 下约 10–17 s 的物理响应。【可以改进的地方：将冲激响应换成自己建模的冲激响应。】
  • 波束形成频带：论文用 (0.5, 2.0) Hz 频段，车辆 DAS 信号能量集中在这附近；1000 Hz 的奈奎斯特频段大部分是噪声。

建议：低通滤波 + 降采样到 50–100 Hz，例如 scipy.signal.decimate(x, 10)（先滤后抽，避免混叠）。这样 win=1024 对应 10–20 s，论文的模型和 pipeline 几乎原样可用。坚持 1000 Hz 需要把窗口放到 ~20000 点、kernel 重采样到 ~17000 点，卷积成本高且没有信息增益。

另外两点：模型输入是 24 通道（data_shape=(24, 1024, 1)）【24是所有的通道数量】，你的光纤通道数不同需要按自己的 Nch 重训；gauge=3.2 m 是他们的道间距，也要换成你自己的。3.2*24=76.8m.

Q2：需要人工标注轨迹吗？¶

训练不需要。 这个方法是自监督/物理约束的：只需要原始 DAS 记录 y 和已知的 h，损失在观测域比较 y 与 h⊛x̂，全程没有标签参与。

picks_forward.npy / picks_backward.npy（人工拾取的车辆轨迹）只用于评估：Fig10/11 里用 match_peaks 把算法检测结果和人工拾取对比，画 ROC 和检测统计。

标准的 FFT 会产生频谱泄漏和高方差，先用多个正交的 Slepian 窗对信号进行加窗处理，再对多个加窗后的频谱求平均，得到稳定、低方差的协方差矩阵，这对于嘈杂信号（如脑电波、微弱地震波）极其重要。

求一维信号的协方差矩阵————滑动窗口延时构建矩阵
矩阵求自相关————得到协方差矩阵，怎么求的？
正交分解，按特征值大小分为信号空间和噪声空间
通过信号空间与噪声空间正交，确定特征值和特征向量
噪声空间对应特征值置为0，再恢复信号

一维阵列采集的二维信号怎么计算协方差矩阵？

频域法
转为频域  >>  多次快拍(多个短窗口)的频域平均  >> 求外积并平均

求外积并平均：在特定频率 f 下，空间协方差矩阵是这样算出来的： $$ R_{xx}(f)=\frac{1}{K}\sum_{k=1}^{K} X_k(f),X_k(f)^H $$

  • Xk(f) 是一个列向量 (M×1)。

  • Xk(f)H 是一个行向量 (1×M)。

  • 它们相乘（外积）恰好得到一个 M×M 的复数矩阵。

  • 把 K 个短窗口算出来的矩阵加起来求平均。

信号到达方向

MUSIC 或 传统 Beamforming 算法寻找信号到达方向（信号到达方向对应车辆速度）

对一维阵列，根据阵列传感器的间距和角度关系，计算对应的延时量，截取多个快拍，从而计算二维信号的协方差矩阵
